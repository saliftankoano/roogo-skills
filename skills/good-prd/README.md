# Good PRD

Turns a feature request into product requirements documents that an approver
can say yes to, and engineering can build from, without a meeting.

## What you get

- **One PRD per ask.** A message with five asks becomes five PRDs, each
  answering "what are we doing?" with one thing, cross-linked, with
  non-overlapping scope.
- **Evidence, not guesses.** The agent reads the code, data and logs first and
  cites what it found: current behaviour, numbers with their date and source,
  conflicts with pricing or policy.
- **The standard structure:** summary, problem with Before / After, goals and
  non-goals, users, requirements (ID, Must / Should / Could), constraints,
  dependencies, 2 to 4 metrics with a guardrail, open questions with a
  recommendation.
- **Drafts until approved.** Nothing is presented as decided until the
  approver says so.

## Example prompts

- "Écris les PRDs pour ces changements du formulaire d'annonce."
- "Turn this voice note into PRDs, one per ask."
- "Write a PRD for removing video uploads."

## Where PRDs go

Wherever the project keeps product decisions. For Roogo: the business vault,
`06 Product and technology/`, one note per PRD named `PRD - <subject>`, linked
from the roadmap note.
